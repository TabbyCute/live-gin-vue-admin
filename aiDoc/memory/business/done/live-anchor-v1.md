# LiveAnchor 第一版主播身份与管理模块

## 基本信息

- 提出日期：2026-09-21
- 当前状态：`done`
- 需求类型：客户端主播身份 / 后台主播管理
- 优先级：高
- 需求文件：`aiDoc/memory/business/done/live-anchor-v1.md`

## 用户原始意图摘要

沿用现有 gin-vue-admin 分层、客户端独立 JWT 和管理后台 JWT + Casbin，实现 LiveAnchor 第一版 7 个 APP 接口与 12 个 ADMIN 接口，并完整补充 Swagger、状态边界和业务注释。

## 影响范围

- 后端 Model：新增 `LiveAnchor` 实体、集中状态常量和表注册。
- 后端 DTO：新增主播 APP/ADMIN 独立请求与响应结构。
- 后端 Service：新增申请、资料、资格检查、审核、状态、权限和运营管理逻辑。
- 后端 API/Router：新增 19 个 v1 路由，后台接口接入现有 JWT、Casbin 与操作日志。
- 系统初始化：登记 12 个后台接口；新增独立“直播管理 → 主播管理”菜单，并只为超级管理员 `888` 补齐初始菜单与 Casbin 权限，不扩散到其他角色。
- 管理后台：新增主播列表、组合筛选、详情抽屉以及审核、账号状态、功能权限、资料、认证、推荐、签约、公会、风控和备注操作。
- 文档：生成并同步 Swagger 文档。
- 使用说明：新增主播申请、审核、开播、封禁和常见问题排查文档。

## 已确认约束

- APP 不接受 userId，以客户端 JWT 的 accountId 实时查询主播。
- JWT 不增加主播状态或权限 Claims，直播/PK 资格实时读取数据库。
- APP 返回独立 DTO，不暴露后台备注、风控、审核管理员和来源 ID 等内部字段。
- `LiveAnchor.ID` 只允许在服务端内部和管理后台出现；APP 请求、APP 响应及公开详情统一使用 `AnchorNo`，不出现 `id` 或 `anchorId`。
- 资料更新使用显式 map 白名单，允许正确写入空字符串、0、空标签和空生日。
- 审核通过与功能权限分离，第一版不自动开启直播、PK 或提现权限。
- PK 资格继承完整直播资格；高风险禁止直播，中风险第一版仍允许；认证第一版不是开播硬条件。
- 注销是不可通过普通状态接口恢复的强状态；封禁到期不在 GET check 中隐式写库。
- AnchorNo 使用“渠道号 + 六位序列(ID+100000)”规则。
- 当前仓库没有 Agency 模型，不创建虚假公会表或外键；接口暂按 ID 更新，待公会模块接入后补存在性/状态校验。
- 已初始化数据库通过幂等元数据同步补建主播菜单；同步只在首次新建菜单时给超级管理员授权，后续启动不会覆盖人工权限调整。
