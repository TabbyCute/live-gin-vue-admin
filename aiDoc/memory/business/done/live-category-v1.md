## 用户原始意图摘要

在不实现直播间、直播场次和推流功能的前提下，先完成独立的 `live_category` 直播分类功能，并提供管理后台页面。

## 影响范围

- 后端 Model：新增 `LiveCategory` 树形分类实体并注册自动迁移。
- 后端 DTO/Service：新增公开分类树、后台分页列表、分类树、创建、编辑、启停和删除逻辑。
- 后端 API/Router：新增 1 个 APP 公共接口和 6 个 ADMIN 接口，并补充 Swagger。
- 主播集成：主播申请、APP 资料更新和后台资料更新开始校验非 0 `categoryId` 必须来自启用分类。
- 系统初始化：新增“直播管理 → 直播分类”菜单、后台 API 元数据和超级管理员初始菜单分配，并兼容存量数据库幂等补建。
- 管理后台：新增分类筛选、分页、树形父级选择、新增、编辑、启停和删除页面；主播管理改用真实分类树选择及名称展示。
- 客户端测试页：新增启用分类树加载和 `categoryId` 自动回填。

## 已确认约束

- 分类 ID 是 `categoryId` 的公开合法值，可以返回客户端；主播数据库主键隔离规则不适用于分类 ID。
- 分类编码规范为小写字母开头，可包含小写字母、数字、下划线和短横线，创建后不可修改。
- 同一父分类下名称不能重复；修改父级时禁止自身/子孙循环引用。
- 停用父分类级联停用全部子孙分类；启用子分类要求全部上级分类已启用。
- 删除只允许已停用、无子分类且未被 `live_anchor.category_id` 或 `live_room.category_id` 引用的分类，并使用软删除；历史场次分类是快照，不阻止删除。
- APP 公共接口只返回启用分类树；后台分类树包含启用和停用分类。
- `categoryId=0` 继续表示未分类或清空分类。
- `live_category` 与媒体库附件分类无关，不复用媒体库分类 ID。
