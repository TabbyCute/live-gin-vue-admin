# 单机排障与后续接入

本轮没有连接SSH或发布应用。以下操作路径在新版本上线后使用；保留旧资金、原幂等键与审计记录，不能用直接修改数据库状态修复业务。

## 先保存定位信息

保存服务端响应头`X-Request-ID`、发生时间/时区、接口、本人订单号及原业务`requestId`。`X-Request-ID`由服务端生成，用于日志关联；业务requestId用于永久幂等，不能混用。不要把密码、token、完整银行账号、回单或备份内容粘贴到普通日志/工单。

root运行状态页展示数据库/Redis、连接池、在途HTTP、worker和出款积压。计数是进程内累计，重启归零；1000+是下界，未知值不是0。worker连续3次失败或停滞出现页面警告；目前没有外部告警接收方。生产应另行接入进程存活、ready、磁盘、数据库备份和页面指标的持续监控。

| 现象 | 应检查 | 正确处理边界 |
| --- | --- | --- |
| 注册/充值 | 认证限流、号码归属验证、原外部单号 | 本轮未接真实短信或充值渠道；共享注册码不能证明号码归属。模拟渠道不能被当作生产资金来源 |
| 送礼超时/重复点击 | 原账号+requestId的礼物结果、钱包流水、trace | 原键原参数查询/重试，不新建键猜测结果，不手工改余额 |
| 收益核验超时 | 审计任务历史快照、进度/issueCode、数据库等待和历史事实规模 | 报告不是付款凭据；不能绕过源证明。在线8秒/后台30秒仍可能被超大历史触及 |
| 出款unknown | 原出款单/attempt、公司账户、银行流水、调查证据和状态历史 | 禁止盲目重付、释放冻结或强改paid；走既有调查与独立复核 |
| 银行账单差异 | 公司/收款指纹、币种/金额/流水、账期、完整性声明、attempt版本 | 部分文件未见不是未付款。跨日、手续费、撤销、更正需真实银行调查，不能据差异自动补付 |
| 事件blocked/dead | 通道配置、稳定eventId、lastCode、租约尝试和重试代次 | 无Adapter时blocked正常反映未接入。仅持久确认可delivered；受控重试仍使用原下游幂等键 |
| 在线人数未知/Redis故障 | ready、presence worker、epoch/检查点、恢复记录 | stale不按0显示；统计恢复不能改资金或广播私人出款消息 |
| 数据库不可用/连接池等待 | ready503、inUse/maxOpen、waitCount变化、任务持续失败 | 不把请求超时当作交易一定失败；恢复后先按原键查询，核对原账本 |
| 日志权限/磁盘错误 | 服务标准错误、日志目录属主/权限、文件数量与磁盘空间 | 私有根目录0700、当前文件0600；日期+64MiB轮转。禁止以外部字段拼日志目录 |
| 迁移失败 | stage/failureCode、cleanupFailed、安全progress和已完成备份SHA | 未核验不等于已变账。先确认是否有部分DDL；不删表或用旧备份覆盖正在写入的生产库 |

`payout_old_pending_confirmation`表示订单创建超过1小时且当前待复核，不是实际进入复核队列满1小时。判断真正审核等待时间应查看该attempt的SubmittedAt。

## 停止与恢复

SIGTERM先进入draining，使ready失败，再等待HTTP最多15秒；随后各worker在自己的预算内停止。Compose已预留60秒；其他进程管理器也应覆盖HTTP和worker总预算。新的SIGTERM子进程测试仅验证本地行为，远程运行环境尚未验收。

服务重启后，事件旧租约按未知结果处理，以稳定键重投；真实下游必须持久去重。收益审计中断后只能重新核验，不能续用旧快照当作付款证据。presence使用既有检查点恢复；本轮资金终态、幂等映射与历史审计不自动删除。

## 后续扩展位置

- 实时通讯：在启动组装实现`eventdelivery.Adapter`，尊重context和有限并发，核验事件ID/幂等键的持久Ack。执行room/user audience授权；私人出款状态不能广播。聊天命令和成员授权仍需实际IM产品接口设计，本轮没有假WebSocket成功入口。
- 真实充值：本地`internal/testpay`仅测试接口与签名模拟，不是微信/支付宝SDK。真实对接需独立持久回调收件记录、官方验签、固定商户订单/金额/币种、查单补偿和退款状态机；不能挂上测试sink冒充真实充值。
- 外部银行：现支持标准化账单声明+人工核对。相同流水的状态更正不可覆盖旧行；银行更正版本、拆合单和净额清算需追加式设计与独立测试。
- 大历史核验：需要独立可信变更记录、完整依赖失效协议及历史损坏验证，才可安全引入增量检查点。单纯缓存余额或签名账户version会漏掉历史来源变化。
- 容量与归档：按实际CPU/内存/磁盘、房间热点、请求分布和SLO再验收。事件和金融事实不能为了省空间直接清理永久幂等记录；先设计归档与可核验查询。

生产验收还包括真实域名/TLS/反代、进程管理器、外部渠道、异常资金核对及实际备份恢复演练。当前本地结果与prod结构迁移不替代这些运行证据。
