# 礼物第一阶段

本文记录礼物模块。后续已补齐 [收益结算与提现审核](../earning/README.md) 和 [人工出款](../payout/README.md)；2026-11-04 接入独立 [主播守护](../guard/README.md) 与 [APP 榜单](../ranking/README.md)。礼物产生的 COIN 事实必须经过独立结算，不能直接视为法币或可提现余额。守护是否已经发布/开售以守护部署记录为准。

## 已实现

- 分类、礼物新增修改、启停、版本冲突保护、完整集合排序、使用中禁止删除。
- APP 启用分类/礼物列表、直播间可用礼物、送礼、原幂等键查询、本人消费记录。
- 后台部分/全额退款、消费记录与关联事实、六维净消费排行及全平台收入汇总。
- 送礼必需的分成规则新版本、双人复核、固定范围优先级、主播待结算收益与退款冲减事实。
- 同库事务广播发件箱、守护授予/补偿命令和事务外履约。IM 未接入时事件保持 pending；守护未通过完整就绪核验时不能启用售卖。
- 直播管理菜单下礼物分类、礼物配置、礼物消费记录、礼物消费排行、主播分成规则五页。
- 主播、房间、场次后台详情的礼物收入汇总；场次列表批量汇总。需要独立 `/gift/ranking` 读授权。
- Swagger、离线迁移、启动结构核验、不可变触发器、真实 MySQL/SQLite 测试、客户端接口安全测试、前端交互回归。

入口：[客户端礼物对接](frontend-client-integration.md)、[APP 与后台接口](api.md)、[事务和扩展契约](accounting.md)、[部署与权限](deployment.md)、[测试与交付记录](testing.md)。

## 数据表

| 表 | 职责 |
| --- | --- |
| gift_category / gift_item | 分类、定价、资源地址、排序、版本与关闭状态的守护规则 |
| gift_order | 送礼事实，用户/主播/房间/场次/分类/礼物/价格/动画/分成/权益快照 |
| gift_refund_order | 永久幂等退款单，原订单、件数、原因、审核操作者、钱包退款引用 |
| gift_revenue_ledger | 只追加正向收入和负向退款收入，按订单关联上述完整维度 |
| gift_event_outbox | 同事务产生的待投递展示事件，不包含钱包余额或内部ID |
| gift_benefit_grant | 为送礼用户产生守护权益的事实边界，目前不创建无法履约的权益 |
| gift_benefit_compensation | 每个退款单唯一的权益补偿事实，接入守护后必须履约 |
| gift_control | 配置及规则变更排他锁、送礼共享锁和排序目录版本 |
| gift_admin_permission | 按角色、完整路径、HTTP方法授权，独立于菜单 |
| gift_audit_log | 不可改删的配置、规则复核、退款审计，含操作者/IP/快照 |
| anchor_revenue_rule | 分成规则版本及双人复核状态 |
| anchor_rule_termination | 提前终止申请及另一位管理员复核，不改写原规则和历史订单 |
| anchor_earning_ledger | 只追加待结算收益与负向冲减 |

已有 wallet 核心 27 个文件相对本任务开始时的 SHA256 完全一致，见 [保留证明](wallet-core-preservation.json)。工作区原本存在钱包未提交修改，因此 `git diff HEAD` 仍会显示这些原有修改；不能把它们归因于本次礼物实现。

基础目录可显式初始化3个分类、6个草稿礼物，草稿价格待运营核定且没有虚构资源URL；重复执行保留已有配置。没有默认分成、汇率、测试用户或虚假订单。结构迁移和目录导入可以分开执行，见部署文档。

## 上线状态

礼物业务已实现并完成本文记录的本机验证。整个管理后台的生产依赖扫描仍有既有高危/中危告警，见测试记录及 `docs/admin-frontend-dependency-remediation.md`；本次没有更改依赖版本或用强制升级破坏已有工具页面。生产容量、网关限制、多实例故障、HA切换、备份恢复和浏览器人工验收仍须在目标部署验证，不能用本机通过代替生产签收。
