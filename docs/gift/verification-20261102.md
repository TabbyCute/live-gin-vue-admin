# 礼物与结算后台优化复验（2026-11-02）

## 交付变更

- 场次列表展示赠送总件数、退款/有效件数及COIN总价值、退款/有效价值，来自真实礼物订单，整页一次聚合。无财务权限或模块未就绪显示“—”；新增grossQuantity/refundQuantity为字符串，不修改表结构。
- 主播管理“创建结算单”固定该主播，与收益结算页共用弹窗；规则分页下拉显示名称、编号、比例、有效期，过期或未生效规则不可选。
- 默认最近7天，截至当前整秒，可自选时间或一键更新。前后端均拒绝未来、空、倒置范围，按收益发生时间左闭右开。金额由后端计算，创建后仍需原有复核入账。
- 确认期间锁定目标、防重复点击；丢响应保留原requestId和参数，关闭重开保持原目标。刷新/页面卸载后需先查结算列表；防重复入账由服务端事务与收益唯一归属保护。
- 修正主播/房间/场次详情的“待结算收益”误导标签：旧字段实际是净礼物分成（含已结算），真正待结算余额读取收益模块overview。

## 性能样本

- 同一热钱包100并发：100笔成功、余额准确归零；约52.57笔/秒，P50 1046ms、P95 1813ms、P99 1885ms。100次同键重放约521ms，无重复扣款/事件。
- 500条收益事实、16并发、64次提现：P50 833ms、P95 854ms、最大858ms；结算创建+批准128ms；最终账户与流水全部核验通过。
- 场次整页只查一次聚合，金额不经JS Number计算，超过int64的汇总仍用精确字符串。

这些是服务层本机样本，不含公网网关、多节点、支付渠道或长期大数据量，不能作为线上SLA。保持每单最多1000收益事实、历史核验20000事实保护上限；更大规模仍需专项容量验收。
