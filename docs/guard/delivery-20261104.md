## 2. 数据表、索引与约束

guard 8 表：plan、membership、grant、compensation、ledger、task、admin_permission、audit_log。ranking 7 表：applied_event、score_bucket、generation_receipt、checkpoint、rebuild_job、admin_permission、audit_log。均加模块前缀。

同一用户+主播关系唯一；来源三元组、授予/补偿编号、任务来源、审计 requestId 永久唯一；RevenueNo 与 source ID 永久唯一，收据按 generation+source ID 唯一；桶完整维度唯一，idx_ranking_board 支持精确分值排序。MySQL InnoDB/utf8mb4_bin，方案状态/天数、补偿与授予量 CHECK，以及事实/流水不可变触发器严格核验。grant 只允许修改可重建的状态/补偿量/到期缓存。

## 3. 守护状态机

方案 enabled/disabled；关系 active/expired；来源按实际剩余区间显示 active/scheduled/expired/compensated。授予、补偿任务 pending→processing→succeeded 或 failed，失败退避、租约过期可接管，20 次后人工处理。旧 lease_token 不能确认新尝试。补偿事实追加即终态，原始申请量保留，实际撤回量记权益流水；先到补偿等待后到匹配来源生效。

## 4. 礼物到守护

充值入账→钱包扣款→gift 订单/收入/收益/BenefitGrant 同事务→提交→独立 Worker→结构化 GuardService→来源事实/当前关系/流水→确认 gift 履约。每件天数×数量由后端计算并冻结；钱包锁内不执行异步履约。

## 5. 退款到补偿

钱包退回原用户→礼物收入与收益冲减→同事务 BenefitCompensation→Worker→按原来源撤回尚未使用部分→重算后续同方案来源区间→确认补偿。已使用历史保留，不通过直接加减总到期时间伪造退款。支持并发、部分/全退、先补后授、成功响应丢失与重试。

## 6. 礼物到榜单

读取未有本代际收据的 gift_revenue_ledger→批量读取原始订单维度→写永久事件→批量原子更新桶→写收据/checkpoint→提交。以来源 ID 排序、以收据补漏，迟提交的较小 ID 仍会处理。重建新代际保留旧榜和历史去重记录，追平后切换；投影失败不回滚已完成的送礼。

## 7. 排行口径

礼物榜为 anchor/room/session 内用户净送礼，可选 giftNo；财富榜为用户全平台净送礼；魅力榜为主播收到礼物的原始净 COIN，可按礼物分类。均排除充值、余额、提现和主播分成影响。Asia/Kuala_Lumpur 自然日/周一/自然月/总榜，退款冲原送礼期间。同分按 subjectNo 升序，名次唯一，金额/件数/排名使用字符串。

## 8. Vue 与菜单

直播管理下已配置守护方案、守护会员、守护权益流水、守护异常任务、直播榜单。角色 888 获新模块精确授权（guard 11、ranking 5）；其他角色不会因有菜单就自动拥有操作权，ID 1 遵循项目超级管理员规则。后台支持方案启停/排序、关系与来源查询、受审计的重试/重建/核验和榜单任务查看。礼物页选择方案和每件天数，能力未就绪禁止启用。
