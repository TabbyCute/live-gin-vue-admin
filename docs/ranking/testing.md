# 排行榜验证（2026-11-04）

整体环境、命令与实际性能见 [守护完整测试记录](../guard/testing.md)。排行榜使用真实礼物财务事实完成 MySQL 流程；另有明确标注的隔离合成来源用例验证超过 int64 的聚合和迟提交，不用于证明钱包正确性，更没有写入生产。

| 场景 | 验证 |
| --- | --- |
| 送礼、部分退款、全退 | 实际充值/扣款/退款服务，逐次消费来源；全退归零且主体不占榜位 |
| 日周月总、范围与 giftNo | MySQL anchor/room/session 与指定 giftNo；不同 category 不串榜 |
| 时区 | Asia/Kuala_Lumpur 自然日，周一、月末边界；跨月退款冲减原礼物期间 |
| 排序与 myRank | 同分按 subjectNo 升序；分页外本人名次仍准确 |
| 大整数 | 两笔 MaxInt64 合计 `18446744073709551614` 精确字符串返回 |
| 中断与晚提交 | 已处理 ID=100 后才出现 ID=10 仍消费；收入永久去重 |
| 故障隔离 | 注入桶写入失败，投影事务回滚，钱包已完成消费保持不变；错误记录后恢复消费 |
| 全量回填/重建 | 独立代际、保留历史事件；逐桶直接聚合核验一致 |
| 批量读取 | 订单、已有事件、桶、公开资料均批量；榜单查询使用完整索引 |
| 外部接口 | APP JWT、访问隔离、参数白名单、有限分页、无内部财务字段 |

数据完整性用 `lagCount=0 + reconcile.consistent=true` 判断，不能只看 lastSourceId。最大 ID 不是已连续提交的游标；代际收据使迟提交来源不会漏掉。

生产执行结果见 [部署证据](../guard/deployment-result-20261104.json)。源/收据/桶核验在生产只读运行，没有添加虚构礼物或直接编辑排行榜分数。生产回填命令本身会写真实来源的派生投影，因此也先备份并限定批量。
