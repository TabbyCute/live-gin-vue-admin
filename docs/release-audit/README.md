# 客户端注册至主播人工出款交付复核

日期：2026-11-09（Asia/Kuala_Lumpur）。范围是新增客户端、直播、社交、钱包、礼物/守护、收益、提现与人工打款功能；后台仅覆盖该资金链必需的操作和共享安全设施。保留工作区原有未提交改动。

## 当前结论

已完成可复现的代码加固、隔离资金链测试及远程正式数据库只读核验。**尚不能签署“企业生产交付全部通过”**：应用未发布，真实短信和银行到账验收、浏览器交互、备份恢复与高可用演练尚未完成。测试不会调用真实银行或写入生产测试账务。

按业务模块的能力、竞态/边界、性能、排障和验收缺口见 [分模块评估](module-assessment.md)。该复核补充指出：SRS 专项日志仍保留 URL 字段原值，开启日志且 URL 携带敏感参数时需进一步脱敏；不能将通用中间件脱敏等同于所有业务日志均已完成验收。

正式库 wallet/gift/earning/payout/guard/ranking/presence 七组结构核验全部通过；payout 核验前后资金摘要和行数一致，迁移及元数据写入均为 false。MySQL innodb_flush_log_at_trx_commit=1、sync_binlog=1、binlog 开启。本轮没有新增列、表或索引，**无需本地或远程迁移**。远程开发库连接超时，未执行任何写入。

## 业务链与验收边界

手机号注册/登录 → 主播申请与独立业务权限 → 人工充值双人审核 → 有效直播场次送礼 → 用户 COIN 扣款和主播收益事实 → 显式兑换规则与结算审核 → 本人加密收款账户 → 提现冻结和审核 → 创建唯一出款单 → 领取与私有凭证 → 独立复核 → frozen 减少、paid 增加、不可变账本/审计/终态事件。

新增 registration_paid_test.go 使用新注册用户贯通实际 Service 和同一个数据库，校验错密码、重复注册、送礼幂等、他人提现账户拒绝、同人复核拒绝、重复成功复核只记一次；最终用户余额 900 COIN，主播 available=35、paid=5、frozen=0、debt=0。SRS 已发布场次和银行回单使用显式隔离测试数据；并非真实推流或银行支付测试。HTTP 鉴权/绑定/路由由各模块测试另行覆盖。

## 本轮修复

| 问题 | 改动与验证方向 |
| --- | --- |
| 正式配置的 CORS 白名单被路由绕过，公网任意 Origin 得到 Allow-Credentials=true | 路由使用 CorsByRules；同源正常 POST 保留；allow-all 不暴露环境 Cookie；恶意源、伪造 Forwarded-Host、同源及预检回归 |
| Gin 默认信任任意代理，部分 ClientIP 限流可被伪造 | 全局使用已有 trusted-proxies 白名单；为空时只信任 TCP 对端；认证已有独立防伪代理实现保留 |
| panic 请求头和原始异常可能泄漏 Authorization/Cookie/参数到日志与错误表 | 仅记录路由模板、方法、服务端 trace、异常类型及栈；错误表写入有 2 秒 context，存储再次 panic 不破坏恢复；日志捕获断言不含注入秘密 |
| 正式环境缺少统一访问追踪 | 全环境结构化 HTTP 元数据；服务端 X-Request-ID 关联礼物、提现和出款审计，拒绝客户伪造；404 不记录原始 URL；不记录正文、头、查询串 |
| 认证后的改密缺少限流/并发/体积保护 | 账户维度限流，与注册登录共享昂贵运算槽；资料及改密正文 ≤4KiB；错误旧密码不计算新哈希，bcrypt 移至锁外，锁内复查密码、token_version 和账号状态 |
| 客户端 JSON 入口慢请求和大正文 | 外层 64KiB、10 秒 context、5 秒读预算；认证/财务继续使用更严格预算；同步处理，不创建可继续写已回收 Gin Context 的后台 goroutine |
| 连接可长时间占用 | HTTP ReadHeaderTimeout=5 秒、IdleTimeout=60 秒；保留现有上传读取预算 |
| 存活探针不能体现依赖故障 | 增加 /api/ready，以 1 秒总预算检查必需 DB/Redis，失败返回 503；不查客户或账务数据；/health 仍只表示进程存活 |
| release 公开调试页面/Swagger | release 模式不注册 Swagger 和 HTML 联调页；开发环境保留 |
| 依赖漏洞 | brotli 升至 1.2.7、compress 升至 1.20.2；无上游修复版本的 MCP Location 漏洞增加请求级同源传输限制、禁重定向、初始化预算和失败关闭连接，专门测试无凭证跨域发送 |

## 运维、发布与未完成项

1. 新增只读预检：在 server 下执行 `go run ./cmd/delivery-check -config config.prod.yaml`；输出结构状态、持久性和配置风险标记，不输出凭证或客户资料，不做迁移。
2. 故障定位：先取响应 X-Request-ID，再查结构化日志 traceId；资金问题继续沿 withdrawalNo → payoutNo → attemptNo → evidenceNo → ledgerNo → terminal event 查询不可变证据。超时先使用原 requestId 查结果，禁止换号盲目重试付款。
3. 监控应对接现有平台：/ready 失败、HTTP 5xx/429/耗时、DB 池等待、死锁/锁等待、Redis 队列积压、worker 租约停滞、财务对账异常、unknown 出款、凭证读写及磁盘容量。此轮未搭建新的告警接收平台或值班系统。
4. 正式跨域白名单还保留示例域名；接入 HTTPS 网关时必须填写实际受信域名，空 trusted-proxies 不信任转发来源。正式配置仍启用共用超级注册码，短信接口只等待后返回。必须接入一次性短信验证与发送审计后才能把手机号当作真实已验证身份；当前测试只证明现有联调流程。没有擅自关闭现有注册业务。
5. 正式运行 DB 账号具有 DDL 权限，应与迁移账号分离并落实最小权限；需同时修改运行配置、发布和验证，不能在未掌握线上部署入口时直接撤权造成服务故障。真实配置含秘密且 prod/dev YAML 当前仍为 Git 跟踪文件，历史密钥暴露审计与必要轮换未完成；发布包权限 0600，禁止公开上传。
6. 已知公网入口为明文 HTTP；HTTPS 域名/证书、网关限流和日志脱敏、数据库网络白名单、私有凭证持久目录/备份、恢复及主从切换尚未完成现场验收。
7. 用户随后已提供服务器访问方式，并要求先做分模块评估；尚未 SSH 连接、重启或替换线上程序，线上 CORS 等旧行为尚未复验关闭。访问凭据不保存到仓库或报告。已生成可校验发布包和配套脚本，但不把“打包成功”当作“发布成功”。
8. 必须由获授权财务用真实公司账户完成银行付款、外部流水核对及独立复核验收；自动测试未执行实际转账。真实实名认证、税务和支付渠道资格不是现有代码测试能够证明的能力。
