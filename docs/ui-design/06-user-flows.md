# 完整用户操作流程

## 1. 路由与权限总流程

```text
打开页面
  ├─ 公开路由 → 立即展示；若本地有 token，后台恢复用户资料
  ├─ guestOnly 登录页 + 已登录 → 跳安全 redirect 或 /home
  └─ auth 路由
       ├─ 无 token → /login?reason=required&redirect=原路径
       ├─ token 存在 → user/info 恢复
       │    ├─ 401/过期 → 清全部账号状态 → 登录页
       │    ├─ 网络验证失败 → 登录页 reason=verifyFailed
       │    └─ 成功 → 检查角色/权限
       └─ anchorApproved 路由
            ├─ applyStatus=2 → 进入
            └─ 其他 → /user/to-anchor?reason=anchorRequired
```

旧主播资料 `/user/profile/anchor/:publicNo` 在认证检查前重定向 `/anchor/:anchorNo`；普通账号资料仍要求登录。

## 2. 注册与登录

1. 游客进入 C-P01，默认登录模式；从受保护页来时显示原因通知。
2. 登录：输入11位中国手机号、8–72字节密码，可记住手机号，勾选协议。
3. 注册：切换注册模式，输入手机→获取6位码（60s冷却）→可选昵称→密码/确认→勾协议。
4. 点击提交后按钮 loading，避免重复；离页会取消当前请求。
5. 登录成功：写入 token/有效期，加载主播身份与社交计数，再 `replace` 原安全地址或 `/home`。
6. 注册成功后自动登录；若自动登录失败，提示“注册成功，但自动登录失败”，保留明确可回登录路径。
7. 401 或 token 过期：清用户、社交、钱包、礼物、收益和开播 sessionStorage，回登录。

异常分支：手机号/验证码/密码/协议校验；短信发送失败；网络/超时；服务端业务错误；恢复会话失败；旧请求取消不显示失败。

## 3. 发现并观看直播

```text
C-P02 首页 → 选择主Tab
  ├─ 热门 → 可选顶级分类 → room/list
  ├─ 新秀/广场 → 当前仍是 room/list（独立规则待确认）
  ├─ 关注 → 未登录先登录；已登录 following-online
  └─ 看过 → 未登录先登录；已登录 history/list → 点击进入账号资料

直播卡 → C-P05 room/detail
  ├─ 非直播/无地址 → 状态面
  └─ 可播放 → HLS + presence open
       ├─ 游客：先拿 guestToken，心跳/在线，不可点赞
       └─ 会员：Bearer心跳、点赞、收藏、关注、送礼
```

进入直播后自动播放；浏览器阻止则点击播放；音频需授权时选择保持静音或开启。离页、切房、切账号、pagehide 尽力 leave；网络恢复触发 presence 刷新。Presence 故障只降级在线数据显示，不停止播放器。

## 4. 直播间社交

- 关注：游客→登录返回；会员点击→单项忙态→成功切“已关注/互关”；失败恢复旧态。
- 收藏：同上，作用对象是 roomNo。
- 点赞：会员且有效 presence；客户端聚合最多10个/次、队列最多100；只显示服务端接受结果，不本地伪增。
- 拉黑：非本人且已登录→危险确认→拉黑同时解除双方关注并隐藏主页；成功后退出/刷新关系视具体页。
- 看在线用户：最多3位会员头像；游客不出资料列表；统计 stale 时显示未知。

## 5. 送礼与结果恢复

1. C-P05 点击礼物；未登录先登录；自己房间/非直播按钮禁用。
2. 加载分类和当前房间礼物；选择礼物、数量或1/10/99预设，实时用 BigInt 展示总COIN。
3. 点击赠送：生成并持久化 `requestId+roomNo+giftNo+quantity`，冻结表单，发送。
4. 成功：用服务端快照显示订单，清 pending，播放本人庆祝动画，重读钱包余额。
5. 断网/超时/503/48003/47012：保留 pending，展示「结果待确认」。
6. 用户点查询：以原requestId调用 result；未找到仍不换键。
7. 允许重试时遵守 Retry-After/指数退避，并以原四项参数发送。
8. 进入 C-P13 可继续恢复、筛选订单、复制客服 orderNo；退款只展示，无客户端申请。

确定失败分支：余额不足、钱包停用、礼物/场次失效、数量超限、无分成规则、主播自送、请求冲突/账务异常。冲突/账务异常保留编号并引导客服。

## 6. 社交关系与观看记录

1. 从个人中心进入 C-P08，默认关注 Tab；或从资料进入共同关注 section。
2. 切换关注/粉丝/互关/看过/黑名单，清旧游标并加载20条。
3. 关系卡点击进 C-P07；按钮执行关注/取消/回关/拉黑/取消拉黑。
4. 看过卡：直播中可进房；删除单条立即移除；清空需确认后进入空态。
5. 卡片/关系 API 部分失败时保留已加载资料并显示局部错误。

## 7. 主播申请

```text
个人中心「创作者中心」 → C-P10
  ├─ 无记录 → 填申请表 → 校验 → 提交 → 审核中
  ├─ 审核中 → 时间线/申请时间 → 等待或刷新
  ├─ 未通过 → 原因 → 重新申请 → 可取消编辑
  └─ 已通过 → 主播资料/权限 → 进入 C-P11
```

身份读取失败不等同普通用户；需显示重试。分类加载失败时保留表单但不能提交缺失分类。重新申请沿用服务端当前主播资料填充，不允许用户修改内部状态。

## 8. 主播开播与中断恢复

1. 进入 C-P11：守卫确认已审核；并行加载身份、资格、房间、当前场次、分类和最近10条历史。
2. 资格不允许：显示原因/banUntil，禁用生成Key；可回主播状态。
3. 资格允许：填写标题、分类、封面、公告、可见范围→保存房间。
4. 生成Key：先保存设置/复核资格→固定 payload 与幂等Key到 sessionStorage→prepare。
5. 成功：展示场次和敏感推流凭证；主播复制到 OBS；页面每10秒同步房间/场次。
6. 页面刷新：若有活动场次且本机保留 pending prepare，显示「恢复Key」并复用原键；不创建重复场次。
7. 有活动场次但无凭证：显示密钥不在本机，可用新且固定的 refreshKey 刷新推流地址；同键失败重试。
8. 结束直播：危险确认→end→清凭证与两个本地Key→刷新房间/历史。

中断边界：prepareDeadline 过期、刷新次数限制、场次已推流/已结束、房间关闭、资格变化均由服务端判定；UI展示服务端安全文案，不能延长截止时间或伪造成功。

## 9. 主播公开主页与管理

### 公开访问

链接 `/anchor/:anchorNo` → 加载资料/相册 → 分别加载贡献榜和守护。游客可浏览/分享/进入公开直播；关注、共同关注、拉黑先登录并返回原页。本人看到「管理我的主页」。主页不可访问可能是不存在、审核、拉黑或权限，不暴露内部原因。

### 管理

1. 已审核主播进入 C-P15，同时加载相册与 settings，互不阻塞。
2. 上传前校验类型、大小和20张上限；操作固定 requestId/version/file。
3. 排序/设首图提交全量 photoNos+version；删除需确认。
4. 成功重读；确定拒绝清 pending；未知结果保留并只允许「重试上次操作」。
5. CAS冲突重读最新版本，用户重新决定。
6. 修改签名/分类以 settings version 提交；冲突同样重读。
7. 私有预览通过认证 Blob；关闭/换账号释放；观众预览进入 C-P06。

## 10. 钱包

个人中心钱包摘要→C-P12→并行余额/流水。余额和流水独立成功/失败；下拉刷新两者；游标加载更多。503+47012 按 Retry-After 加抖动，冷却中刷新只提示剩余时间。回前台超过30秒仅刷新余额。钱包停用仍可看历史，不提供充值/转账/客户端退款。

## 11. 主播收益、收款账户与提现

```text
已审核主播 → C-P14
  ├─ overview + settlement + withdrawal list + payee list
  ├─ 管理收款账户
  │    ├─ 新增银行卡/支付宝/微信OpenID
  │    ├─ 设默认
  │    └─ 停用（不可恢复，确认）
  └─ 申请提现
       ├─ 选择币种/输入金额/选择active同币种账户
       ├─ 确认金额和脱敏账户
       ├─ 保存原四参数并提交
       ├─ 成功：余额冻结、显示审核中
       └─ 未知：查询→原参数重试；不换键
```

提现状态：`pending_review → approved(待出款) → paid`，或 `pending_review → rejected`，或受控人工流程进入 `cancelled`。驳回/取消释放冻结但先抵 debt，UI不得承诺余额完整回原数。

旧版 pending 缺 payeeAccountNo：只查询；服务端明确未找到且距创建≥30秒，用户确认后才清本地记录，再新建申请。浏览器支持 Web Locks 时提交/恢复/清理跨标签互斥；不支持时提示避免多窗口操作属于待确认增强。

## 12. PC、Android、iOS 跳转差异

- PC Web：相同URL路由；弹层可改右侧抽屉/居中对话框；长表单双列；键盘 Esc 关闭、Tab 焦点、Enter 提交。
- H5：底部弹层、系统返回、触控、safe area、VisualViewport 键盘修正。
- Android/iOS：若使用 WebView，路由/数据流程相同；若原生重写，必须保持 requestId、状态机、金额字符串与权限边界。系统分享、剪贴板、相册选取、网络状态和安全存储需原生桥接，方案待确认。
