# H5、PC Web、Android、iOS 差异

## 1. 当前实现事实

| 平台 | 源码状态 | 结论 |
| --- | --- | --- |
| H5 | 有完整 Vue/Vant 源码 | 设计与交互事实基线 |
| PC Web | 同一源码在 `>767px` 切 PC 样式 | 功能共享，布局单独适配；不是 `web/` 管理后台 |
| Android | 无原生/壳工程 | 只能输出目标适配；实现、最低版本、权限待确认 |
| iOS | 无原生/壳工程 | 同上 |

因此：业务流程、数据字段、状态机、权限和文案语义四端共享；导航形态、弹层形态、媒体/系统能力、输入和安全区需要分别设计。

## 2. 共享与独立稿件

| 范围 | 可共享 | 必须独立 |
| --- | --- | --- |
| 业务 | 页面ID、角色、字段、状态、API结果语义、幂等恢复 | 无 |
| 视觉 | 色彩Token、字号层级、状态色、图标语言、卡片基础 | 平台密度、导航、弹层、触控/hover |
| H5/移动App | 单列信息架构、底部Tab、底部弹层 | App原生导航栏、权限弹窗、系统分享/相册/安全存储 |
| H5/PC | 内容和字段、业务卡片 | PC多列、键盘/hover/focus、对话框/抽屉、最大宽度 |
| Android/iOS | 移动页面内容 | 系统状态栏、返回手势、键盘、权限文案、分享/选择器风格 |

至少独立生成：登录、发现、直播间、个人中心、开播台、收益页的 H5 与 PC；App只在技术方案确认后生成原生差异稿。其余页面可用响应式组件+平台标注。

## 3. H5 规范

- 宽度：320–767；主验收390×844和430×932；竖屏为主。直播间可支持系统全屏横屏，但普通页面横屏布局为「待确认」。
- 安全区：顶部/底部使用 `env(safe-area-inset-*)`；底部Tab、礼物面板、提现弹层不得被Home Indicator遮挡。
- 高度：使用 VisualViewport/`dvh`；Safari地址栏、键盘、BFCache、横竖屏变化要重算；页面内部滚动，避免body双滚动。
- 触控：44px目标；无hover依赖；下拉刷新与页面滚动不冲突；横滑Tab/相册需防误触。
- 键盘：表单弹层打开时滚动到当前字段；验证码/金额/手机号使用匹配键盘；键盘弹起仍可看到字段错误和提交按钮。
- 浏览器：构建目标为 widely-available baseline；旧 WebView 若不支持相关基线需单独降级评估。HLS 自动播放、全屏、Web Share、Clipboard、Web Locks 均需能力检测与降级。
- 网络：移动网络切换时显示离线/恢复；presence自动退避；金融写操作保留原请求；大图/动画失败使用静态占位。
- 资源：首屏按路由拆包；HLS、Lottie、QR懒加载；避免直播画面上叠加高成本模糊导致低端机掉帧。

## 4. PC Web 规范

- 断点：768–1023小桌面、1024–1439标准、>=1440大桌面；内容最大宽900/960/1180，不把卡片无限拉宽。
- 导航：当前源码仍是底部居中胶囊三Tab。若改左侧栏属于产品IA变更，先确认；设计平台可输出“保留底Tab”的事实稿和“侧栏建议稿”但不得混为已实现。
- 布局：登录左右分屏；发现2–4列；个人中心2–3列；开播设置/场次双列；相册4–6列；收益概览与记录双栏但保持阅读顺序。
- 交互：完整hover/active/focus；Tab键、Shift+Tab、Enter/Space、Esc；浏览器返回；文本选择与复制；工具提示不遮挡。
- 弹层：简单确认居中；收款/提现对话框；复杂详情可右抽屉；最大高度并内部滚动。
- 播放：直播画面可居中16:9或沉浸满屏，操作层不随窗口过宽散开；全屏按钮与Esc退出；浏览器多标签状态冲突显示清楚。
- 长内容：推流URL/业务号可复制、换行或横滚；余额不得省略；列表过长有分页/加载更多；空白区保持合理密度。
- 兼容：Chrome/Edge/Safari/Firefox目标版本待确认；Web Locks不可用时提现多标签提醒为建议增强。

## 5. Android 目标规范（实现待确认）

- 状态栏/导航栏：edge-to-edge时内容避让系统insets；状态栏图标随主题切换；直播间可沉浸隐藏但退出控件可见。
- 返回：系统Back优先关闭弹层/全屏预览→页面返回→主Tab根页二次退出（是否二次退出待确认）。
- 键盘：IME resize，不覆盖验证码、金额和确认按钮；Next/Done顺序；密码不进自动填充日志。
- 权限：若原生选择照片，申请照片/媒体权限；若原生开播才涉及相机/麦克风（当前产品是OBS推流，不能提前索取）；通知、剪贴板提示策略待确认。
- 系统能力：原生分享、剪贴板、文件选择、网络状态、安全存储、深链需桥接；JWT不得明文落普通Preferences。
- WebView：允许域、文件访问、混合内容、调试开关、下载/上传、HLS解码与全屏必须安全配置；版本基线待确认。
- 生命周期：前后台切换暂停非必要轮询、presence刷新；音频焦点/来电中断后恢复状态明确。

## 6. iOS 目标规范（实现待确认）

- Safe Area：刘海/Dynamic Island/Home Indicator；直播沉浸仍保留可触达退出。
- 导航：左缘返回手势；弹层下拉关闭仅在不会丢失敏感/未确认请求时允许；导航标题遵循iOS层级。
- 键盘：VisualViewport/WKWebView差异；密码/验证码AutoFill标签；金额键盘缺Done时提供附件栏（原生方案待确认）。
- 权限：相册选择使用系统Picker可避免广泛权限；相机/麦克风仅原生推流时申请；`Info.plist` 文案待确认。
- 媒体：iOS HLS原生能力、自动播放、静音、行内播放、全屏与音频会话；用户手势授权必须有设计。
- 系统能力：Share Sheet、Universal Links、Keychain、安全剪贴板、网络切换；WKWebView域与证书策略待确认。
- 生命周期：后台停止轮询/presence并尽力leave，回前台刷新；系统截屏保护iOS能力有限，敏感推流凭证以默认遮罩和教育为主。

## 7. 页面级平台差异

| 页面 | H5 | PC | Android/iOS |
| --- | --- | --- | --- |
| C-P01 | 单列，键盘优先 | 左视觉+右表单 | 原生导航隐藏；Password AutoFill/短信码建议系统能力 |
| C-P02 | 2列紧凑卡/横滑分类 | 3–4列、hover预览仅建议 | 下拉刷新原生感；深链打开直播待确认 |
| C-P05 | 全屏竖屏沉浸，底部功能栏 | 16:9/宽屏沉浸，键盘/全屏 | 音频焦点、画中画/投屏均待确认；不得默认添加 |
| C-P04 | 单列+底Tab | 多列卡片 | 系统设置/登录安全存储桥接 |
| C-P09/10 | 长表单单列、底部Picker | 双列表单、对话式Select | 日期/选择器采用系统组件 |
| C-P11 | 单列，长凭证换行 | 设置/场次双列，凭证网格 | 复制、截屏教育；OBS仍为外部工具，不设计手机推流 |
| C-P12/14 | 金融卡+列表；弹层全宽底部 | 概览+列表；居中Modal/抽屉 | secure storage、跨进程幂等；生物认证不是现有功能 |
| C-P15 | 2–3列相册、系统文件选择 | 4–6列拖拽不在现有能力 | 系统Photo Picker；多选当前未实现 |

## 8. 深色/浅色

- H5/PC 已实现系统跟随和手动持久化，需产出双主题。
- Android/iOS 若原生：跟随系统并可选App内覆盖的产品决策待确认。
- 直播间保持深色操作层；Light模式仅影响非媒体页及弹层Token。

## 9. 待确认清单

1. Android/iOS 是 WebView 壳、跨平台框架还是原生重写。
2. 最低系统/浏览器版本、横屏范围、是否需要Pad/平板。
3. PC主导航是否允许从底部Tab改侧栏。
4. 原生推送、深链、Universal/App Links、通知类型。
5. 是否需要画中画、投屏、后台音频、原生手机开播。
6. 系统权限列表、隐私清单、数据删除/注销入口（当前客户端仅展示注销状态，无发起入口）。
