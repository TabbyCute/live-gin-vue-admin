# AI UI 生成平台专用提示词

> 使用方式：先把「全局主提示词」作为项目级上下文，再按页面复制对应提示词。需要批量出稿时，按文末顺序生成。所有“待确认”必须以设计批注呈现，不能由 AI 自行补业务。

## 1. 全局主提示词

```text
请为一套直播内容社区客户端生成可投入研发的高保真 UI/UX 设计。产品面向观众、普通用户和主播，现有真实客户端为 Vue 3 + Vite + Vant 的响应式 Web，覆盖 H5 与 PC；Android/iOS 只做后续适配稿，不得假设已有原生能力。

设计目标：直播区沉浸、有活力；个人资产和收益区准确、可信、低干扰；主播工作台专业、清晰。使用可替换品牌占位“KPlayer”，不得自行设计正式 Logo。主色 #1989FA（深色 #3F9CFF），成功 #16A34A，警告 #F59E0B，危险 #EF4444；浅色页面 #F5F6F8/容器白色，深色页面 #0B0C0F/容器 #15171C。系统字体，4px 网格，输入框圆角 8px、按钮 12px、卡片 14–16px、底部弹层 20–24px。所有正文达到 WCAG AA，状态必须同时用文字/图标表达。

画板：H5 主画板 390×844，补 320 和 430 宽度；PC 主画板 1440×900，补 1024 收缩态。H5 处理状态栏、底部安全区、浏览器动态地址栏、软键盘遮挡；PC 提供 hover/focus/键盘交互。Android/iOS 仅对系统导航、返回手势、日期选择器、分享、剪贴板、权限与安全区域提供平台变体，并标“容器方案待确认”。

全局导航：首页、榜单、我的三项主 Tab。深层页面有明确返回。观众未登录可以浏览公开首页、直播间、主播主页和榜单；关注、点赞、收藏、送礼、社交列表和资产页需要登录。主播能力只有审核通过身份可用。账号、主播、钱包、房间、场次的受限状态都必须明确说明原因和恢复方式。

每页至少生成：默认成功态、首屏骨架、局部加载、无数据、接口失败可重试、离线/超时、登录过期、无权限、提交中与禁用、成功反馈。列表补下拉刷新/加载更多/到底/更多失败/筛选无结果；表单补空值/焦点/已填/字段错误/服务端错误/重复提交；弹层补打开/确认中/失败保留/取消。不要只用 Toast 承载必须持续阅读的信息。

资金和幂等操作是重点：余额、金额、版本、总数全部按十进制字符串展示，不用浮点近似；超时、断网、503 对送礼、提现、相册写操作和开播准备可能代表“结果未知”，界面必须显示“结果待确认”，保留原 requestId/幂等键和原参数，提供查询或安全重试，禁止直接显示失败并新建请求。提现 approved 的中文必须是“审核通过·待出款”，只有 paid 才是“已付款/已到账”。收款账户绑定不等于实名认证或渠道认证。

不得新增源码没有的业务：直播聊天/弹幕/私信、客户端充值或退款、全房礼物广播证明、守护购买、真实榜单数据、原生推送、相机直播、系统支付、第三方登录、忘记密码、国际手机号。聊天和“更多”在直播间必须显示为禁用占位。榜单必须有“数据接口待接入”设计批注。测试和演示路由不生成正式业务稿。

输出应包含：页面高保真稿、组件和状态变体、交互注释、字段/文案、页面跳转连线、H5/PC差异；需要原生差异的页面再补 Android/iOS稿。图标采用统一线性图标，图片失败使用品牌渐变占位，敏感值默认遮罩。所有按钮至少有 default/hover/pressed/focus/disabled/loading 变体。
```

## 2. C-P01 登录/注册

```text
设计“登录/注册”页。用途是建立客户端会话，并在成功后安全返回用户原访问页。H5 为顶部品牌占位+单列表单，底部避开键盘和安全区；PC 为左侧克制的直播品牌视觉、右侧居中表单卡。提供登录/注册双 Tab。

登录字段：仅中国大陆 11 位手机号、8–72 字节密码、记住手机号、密码显隐、协议勾选、登录。注册字段：手机号、6位短信码及发送按钮、昵称可选且不超过64字符、密码、确认密码、协议勾选、注册并登录。短信按钮包含发送中、60秒倒计时、失败可重试。输入错误紧贴字段；协议未勾选阻止提交。

状态稿：默认、字段焦点、字段错误、登录中、短信倒计时、短信失败、登录失败、网络/超时、会话过期/缺少认证/认证失败顶部通知、注册成功但自动登录失败。成功后 replace 返回安全 redirect。协议链接新窗口打开。不要增加忘记密码、第三方登录、国际区号。正式 Logo、品牌名和协议地址标“待确认”。
```

## 3. C-P02 直播发现首页

```text
设计“直播发现首页”。顶部内容 Tab 为关注、热门、新秀、广场、看过；热门下有“所有+顶级分类”横滑二级 Tab。主体展示直播卡：封面、直播/看过标签、观看量、头像、昵称、标题。底部固定首页/榜单/我的三项主 Tab。

H5 使用可读的两列直播卡或窄屏单列；PC 在最大内容宽度内使用2–4列网格。标题最多两行，图片失败为品牌渐变占位。切换主/子分类会重置分页；支持下拉刷新、滚动加载、加载更多失败和到底。公开直播卡进直播间；看过卡进账号资料；关注/看过未登录时显示登录引导并保留返回地址。

分别设计分类加载失败但直播列表可用、首屏骨架、各 Tab 空态、接口失败、断网、分页加载和图片失败。新秀/广场当前没有专用 API 筛选参数，在交互注释中标“排序/筛选规则待确认”，不得暗示已有独立算法。
```

## 4. C-P03 主播热度榜

```text
设计“主播热度榜”视觉方案，但明确它当前是数据未接入的产品占位。页面含日/周/月分段控件、名次、头像、主播名、分类、热度、更新时间和口径说明；前三名可有克制差异化。底部保留首页/榜单/我的主 Tab。

生成加载骨架、空榜、接口失败、并列名次、超长热度数字、更新时间缺失等状态，并在页面批注“榜单 API、排序口径、刷新频率、详情跳转均待确认”。不得使用源码中的5条静态数据作为正式内容，不得添加财富榜、打赏榜或主播点击跳转。
```

## 5. C-P04 个人中心

```text
设计“个人中心”作为用户资产、社交与创作者能力总入口。头部展示头像、昵称、脱敏手机号、签名、账号编号、账号状态和主播身份徽标。主体卡片包括钱包、礼物消费记录、关注/粉丝/互关/看过/黑名单；审核通过主播再显示收益、主播统计、主播主页管理和开播入口。普通用户显示申请主播；审核中显示进度；驳回显示原因与重新申请；已通过显示认证主播。

H5 单列卡片并保留底部主 Tab；PC 用2–3列仪表盘。钱包、社交、收益摘要分别加载和失败，一个模块失败不能清空整页。身份读取失败不能误判为普通用户。设计账号正常/停用/封禁，主播审核中/驳回/通过/受限，资产数字超长等变体。退出需危险确认、提交中禁重复，成功回登录页。

跳转：账号设置、钱包、礼物记录、收益、主播主页管理、主播申请、开播台、社交中心。未审核用户点击开播应提示并转主播申请页。
```

## 6. C-P05 直播间

```text
设计沉浸式“直播间”。视觉层从后到前为：房间/播放状态层、模糊封面背景、HLS画面、始终可操作的顶部与底部控制层。顶部含主播头像昵称、在线人数、关注、最多3位在线会员头像、拉黑菜单、退出；底部含禁用的聊天占位、收藏、点赞、禁用的“更多”、礼物。自己房间隐藏关注/拉黑并禁止送礼。

房间和播放器状态必须独立覆盖：进入中、roomNo缺失、房间失败、未开播、准备中、结束中、已结束、不可播放、播放器初始化、视频加载/缓冲、自动播放被阻止、手动播放、媒体失败、直播结束。任何状态都保留退出；错误提供重试。自动播放可先静音，弹层提供“继续静音/同意并开启声音”，浏览器拒绝后仍可静音观看。

Presence 显示会员+游客总在线；统计失败写“在线人数同步中”而不是0，网络恢复自动重连，不能因统计失败暂停合法播放。游客可观看，点击关注/收藏/点赞/礼物时进入登录并返回本页。关注、收藏、点赞有局部 busy 和失败回滚；拉黑有危险确认。

礼物底部面板含分类、礼物图/珍稀标签、余额、数量输入、1/10/99预设、总 COIN、发送、礼物历史和钱包入口。覆盖目录加载/空/错、余额不足、钱包停用、自送、场次结束、规则无效、频率限制、发送中、成功本人动画、超时/断网/503“结果待确认”。结果未知必须保留原请求并提供查询/安全重试；成功动画只代表本人确认，不写“全房广播成功”。不得设计可输入聊天、弹幕或更多功能。
```

## 7. C-P06 主播公开主页

```text
设计公开“主播主页”。上部为照片轮播和身份卡，展示头像、认证、主播号、等级、地区、语言、标签、简介、关注/粉丝、关系按钮。中部显示直播卡；下部显示贡献榜（日/月/总）和守护信息；顶部提供分享，本人显示“管理我的主页”。游客可浏览，关系操作需登录并返回本页。

相册支持空态、缩略图、左右滑动和全屏预览；预览含计数、关闭、键盘方向键、单图失败重试。贡献榜首屏3人，展开后20条/页，有上一/下一页，超过2000说明范围。守护覆盖功能关闭、无守护、有守护、服务端明示权益；不能新增购买按钮。

关系状态覆盖关注、已关注、互关、回关、共同关注、拉黑；拉黑危险确认后主页可能不可访问。分享面板含二维码、canonical 链接、复制、系统分享，失败时降级为复制/长按。设计整页加载、主页不存在/无权限、空相册、各分区独立失败、直播中/未开播。分享链接不得含 token 或原查询参数。
```

## 8. C-P07 用户资料

```text
设计登录后可访问的“普通用户资料”页。展示头像、昵称、签名、账号编号、关注/粉丝数；非本人显示关注/取消/回关、共同关注、拉黑；正在直播时显示进入直播按钮。本人态隐藏关系操作。

状态包括加载骨架、资料不存在、无权限、被拉黑、关系局部加载/失败、图片失败、账号受限。卡片跳社交关系列表或直播间。主播旧资料地址会自动跳主播主页，因此本页不要重复设计主播完整主页能力。H5 单列，PC 居中窄内容区。
```

## 9. C-P08 社交与内容

```text
设计“社交与内容”统一列表页。可见 Tab 为关注、粉丝、互关、看过、黑名单；共同关注由资料页深链进入，标题随目标变化但不作为常驻 Tab。用户卡展示头像、昵称、账号、关系描述、直播红点和关系操作；观看历史展示最近观看时间、进入直播和删除。

支持横滑 Tab、下拉刷新、游标分页、到底、更多失败、逐项 busy。点击用户进入普通资料或主播主页；关系按钮支持关注/已关注/互关/回关/取消拉黑/拉黑。删除历史逐项确认；清空历史用不可恢复确认，成功后直接空态。

每个 Tab 有独立空文案、加载骨架、接口失败、筛选无结果；操作成功后更新或移除当前项，失败保留。H5 用卡片列表，PC 使用最大960px的双列或宽列表，但字段和操作一致。
```

## 10. C-P09 账号设置

```text
设计“账号设置”。分为账号概览、个人资料、修改密码和认证只读信息。资料字段：头像 URL与预览、昵称必填≤64、签名≤255、性别、生日不得晚于今天、国家2字母、地区/城市≤32、语言≤16。密码区含旧密码、新密码、确认密码，各8–72字节，三项分别可显隐，新旧不能相同且确认一致。手机号和实名认证状态只读，写明“暂不支持客户端修改”。

生成默认、已修改、字段错误、保存中、保存成功、服务端失败保留输入、改密中、改密成功并轮换 token、服务端未返回新 token 后退出并提示重新登录。H5 处理键盘和滚动首错；PC 分卡布局。Android/iOS 日期用系统选择器；防截屏能力标“待原生容器确认”。
```

## 11. C-P10 主播申请

```text
设计“主播申请/审核进度”页。首次申请表单含性别、出生日期、直播分类必选、主页封面 URL、国家/地区/城市、语言、标签 ID 逗号格式、签名≤255；顶部解释审核流程。分类使用底部选择器或PC弹层，含加载/空/错误。

身份状态卡覆盖：身份读取中、读取失败可刷新、未申请、审核中、已通过、未通过并显示拒绝原因。展示主播号、申请/审核时间和三步时间线。审核中禁重复提交；驳回后允许重新申请；已通过进入开播台。提交中整表禁用并滚到首个错误。

标签当前是数字 ID 文本输入，不要擅自改成可搜索标签组件；若视觉上提供标签选择器，必须标“标签数据源待确认”。
```

## 12. C-P11 主播开播台

```text
设计专业的“主播开播台”。顶部显示直播间标题、房间号、未开播/准备中/直播中/结束中状态和同步时间。资格卡显示允许或拒绝、服务端原因、限制截止时间；资格拒绝时禁用生成 Key。

设置区字段：标题≤128、分类必选、封面≤500、公告≤500、可见范围公开/关注者/私密；操作为保存、恢复关闭房间、生成 Key。当前场次展示场次号、流名、开始时间、在线、观看、点赞；无场次为空态。凭证区默认遮罩 publishToken、幂等 Key、Push URL、Stream Key，可显示/隐藏/复制，明确“等同直播密码”和有效期；下方是 OBS 三步配置指南。

刷新后若检测到原 pending prepare，显示“恢复Key”；有场次但本机无凭证时提示“推流密钥未保存在本机”，只允许刷新 Push URL。超时/断网/503 为结果未知，不得新建场次。结束直播需危险确认；成功清本地凭证并刷新。活动场次仅前台每10秒同步，静默失败后提供手动同步。

PC 使用设置/场次双列和宽凭证区；H5 单列，长 URL 可换行或横滑。状态稿包括资格加载/拒绝、无房间/房间关闭、保存失败、生成中、等待推流、直播中、结束中、凭证丢失、恢复中、结束失败。
```

## 13. C-P12 我的钱包

```text
设计只读“我的钱包”。余额卡展示 COIN 可用余额、冻结、钱包状态、版本和更新时间；大额数字必须完整、使用等宽数字。流水卡展示业务类型、时间、变动额、变动前后和短流水号，业务类型仅人工充值、冲正、消费、退款或“余额变动”。提供刷新、下拉刷新、游标加载更多。

余额和流水分别加载、分别失败；有旧数据时用内联错误条而不是清空。状态包括正常、钱包停用、账务异常不可重试、503+Retry-After倒计时、无流水、更多失败、离线。回前台超过30秒只刷新余额，冷却内禁重复请求。不得出现充值、转账、退款或内部 businessNo。
```

## 14. C-P13 礼物消费记录

```text
设计“礼物消费记录”。顶部在存在未确认请求时显示持续警示和查询/安全恢复操作。筛选为全部、已完成、部分退款、已全额退款。订单卡含礼物图、名称、数量、总额、退款、净消费、时间、客服订单号和复制；图片失败用统一礼物占位。

覆盖首载骨架、空记录、接口错误、加载更多/到底、429冷却、待确认查询中、查询成功后刷新钱包、查询仍无结果、客服冲突。断网/超时/503必须显示“结果待确认”，保留短 requestId 并提示不要重复发起；不能提供客户端退款按钮，也不展示内部钱包和分成字段。
```

## 15. C-P14 主播收益

```text
设计“主播收益”综合页。顶部显示多币种可提现余额、冻结、已付款、待抵扣/账本版本；下方为待结算/累计结算摘要、结算记录、收款账户入口、人工出款说明、提现筛选和列表。提现状态为全部、审核中、审核通过·待出款、驳回、已付款、已取消；approved 绝不能写成到账。
```

## 16. C-P15 主播主页管理

```text
设计“主播主页管理”。相册区显示已用/上限，照片网格含缩略图、审核中/已通过/未通过/已下架标签、拒绝原因、首图标记；操作为上传、设首图、前移、后移、删除。只允许 JPG/PNG/WebP、1字节–8MB、最多20张；满额禁用上传。上传后必须显示等待审核，不得直接视为公开。

相册写操作出现超时/断网/503时显示“结果待确认”，保留原 requestId/version/file/photoNos，并提供“重试上次操作”；期间其他写按钮禁用。版本冲突刷新最新相册并提示重新操作；明确拒绝才清 pending。删除需确认；私有大图预览关闭后释放资源。

公开介绍区含签名≤255实时计数、内容分类、版本保存；覆盖成功、失败、版本冲突。提供“观众视角”跳主播公开主页。H5 使用可重排两列网格，PC 使用3–5列并保留操作可发现性。
```

## 18. 不生成正式设计的页面

- C-P16 `/play`：播放器调试台，不进入正式信息架构。
- C-P17 `/movies`、`/moives`：只有占位文字，不得推演电影业务。
- C-P18 `/about`：只有占位文字；品牌、版本、协议、隐私、客服和许可证确认后再生成。
- C-D01~04：组件、刷新、HLS、短视频虚拟列表测试路由；产品要求是隔离，不是美化。

## 19. 推荐批量生成顺序

1. 先生成全局组件库和 C-P01、C-P02、C-P04，锁定品牌基线、主壳与响应式规则。
2. 生成 C-P05、C-P06、C-P07、C-P08，统一直播与社交关系状态。
3. 生成 C-P10、C-P11、C-P15，统一主播生命周期与幂等提示。
4. 生成 C-P12、C-P13、C-P14，统一金额、订单、待确认和危险操作语义。
5. 最后生成 C-P03、C-P09、C-P19，并补齐所有状态画板与 Android/iOS 差异稿。
