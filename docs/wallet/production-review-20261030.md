# 钱包封版审查（2026-10-30）

## 结论与范围

钱包代码可作为封版候选：人工充值、审核/驳回/冲正、消费扣款/退款、身份隔离、幂等、事务回滚、竞争和后台追踪已执行本机真实MySQL回归，并修复本报告列出的缺口。**这不是无条件生产上线批准**：管理端公共依赖仍有11项生产依赖告警，实际网关限流、生产容量、备份恢复和数据库故障切换尚未验收。没有足够证据宣称“顶尖企业生产能力全部验证通过”。

本轮未增加或修改数据库表、字段、索引、CHECK或触发器，未删除远端表、未写入业务库、未改动生产配置；不用清库重建。现有社交模块及此前钱包扣款/退款工作保留。新增前端issues为响应字段，不是数据库列。

## 已复现并修复

1. **首次审核缺少申请审计核验。** 在无保护触发器的故障恢复库模拟删除、修改或重复创建审计，原代码仍可首次入账。现在先验证申请审计完整性，异常返回47011，开户、余额、额度、流水均不产生新写入；旧legacy申请仍按既有47015拒绝充值，保留驳回路径。
2. **已完成审核重试校验不足。** 凭证、请求摘要、流水原因、原流水关联等损坏时原代码可能返回成功。现在重算请求摘要，核验流水金额算术、原因、原单关联及当前尾流水；冲正入账前再次核实原入账审计与流水。RC事务下核对尾流水使用钱包共享锁，真实MySQL暂停查询实验验证并发扣款不会制造混合版本误报。查询详情与批量对账仍用无资金行锁的只读快照。
3. **入口缺少过载控制，context不能中断慢正文。** 增加APP64/后台16的独立可配置在途上限、503/Retry-After、鉴权前APP超长输入拦截和8秒底层读取期限。真实TCP验证慢正文中断、槽位释放、未发送完的超大正文快速拒绝；同一上限没有无界排队或IP内存表。它不替代网关全局QPS/连接限流。
4. **异常日志可能泄露原始依赖错误，坏JSON脱敏失败会退回明文。** API只记录安全分类及MySQL编号；通用操作日志解析失败/脱敏溢出隐藏整段，写日志有独立2秒期限，防止数据库异常耗尽请求槽。财务审计仍是资金事务的一部分，不能以通用日志失败为由省略。
5. **人工充值追踪在流水缺失时整体失败。** 详情与交易溯源现在保留现存订单、审计并返回issues，后台显示红色告警；审核重试仍拒绝成功，不补造流水、不改余额。完整核验必须继续使用三游标对账。
6. **管理端共用Axios版本较旧。** 从1.8.2更新为1.21.0，加入冻结pnpm锁文件；真实HTTP客户端测试验证鉴权、手机号编码、超过2^53的金额字符串、503传播及相同参数重试。前端生产依赖告警从45项降为11项，未进行无依据的全项目大版本升级。

## 实测证据

环境：macOS amd64、12逻辑CPU、Go1.26.10、Docker MySQL8.0.46；测试连接池24，刷盘/binlog参数均为1。每个MySQL测试使用独立wallet_test_随机库，限定127.0.0.1:13326，结束删除。未配置的其他模块外部集成测试按既有规则跳过；钱包MySQL场景实际执行。

- 注入本机DSN的全仓`go test ./... -count=1`通过；新增修改再执行钱包专项与race回归。
- 钱包Service/API/Router、initialize、config、middleware的race回归通过；`clientFoundRows=true`下Service与middleware回归通过，无Go数据竞争报告。
- `go vet ./...`与`go build ./...`通过；Swagger重新生成。
- 金额fuzz 46,410次、JSON fuzz 20,903次通过；不是穷尽输入空间的证明。
- 管理端12项测试通过（11项Vue逻辑+1项真实请求客户端），生产构建通过；已有大资源分块提示仍存在。
- govulncheck：0个调用可达漏洞；另外7个已导入包、2个依赖模块告警未被判定为当前调用可达。见[vulnerability-result](vulnerability-result-20261030.txt)，不能简称“所有依赖无漏洞”。

真实MySQL场景继续覆盖：跨管理员凭证防重、首次开户竞争、充值/消费/退款混合写入、余额不足争抢、退款总额争抢、停用/注销竞争、外层事务旧快照、死锁/锁等待/context取消、最终审计失败全回滚、提交成功但响应丢失后的同单恢复、MaxInt64/版本耗尽、最多1000次分退款、不可变触发器、错误schema启动拒绝、全部查询计划和三游标完整对账。APP/ADMIN令牌隔离、旧权限/失效账号、未知/重复字段及参数、任意金额HTTP路径不开放继续通过。

## 发布前仍需关闭的事项

- **管理端供应链告警：4高、7中。** 分布于旧wangeditor（表单设计器间接依赖）、ECharts、PostCSS相关包、vue-template-compiler、qs、source-map-js。钱包页面不使用富文本或图表，当前未证明这些告警在钱包路由可利用；但同源管理后台不能据此忽略风险。后续处理步骤见[管理后台前端依赖安全整改清单](../admin-frontend-dependency-remediation.md)，原始扫描路径及修复版本见[结构化审计结果](frontend-dependency-audit-20261030.json)。其中[旧wangeditor公告](https://github.com/advisories/GHSA-g7mw-5cq6-fv82)没有补丁版本，[ECharts公告](https://github.com/advisories/GHSA-fgmj-fm8m-jvvx)要求6.1.0，需要对相关组件做独立迁移/回归或给出可达性处置依据。Axios已按[相关安全公告](https://github.com/advisories/GHSA-pf86-5x62-jrwf)及当前扫描修复版本更新。
- **实际入口与持续容量。** 按真实硬件、实例数、数据量、热点账户比例测持续负载/过载恢复；配置TLS、网关连接/速率/慢请求限制，确认后台网络边界与角色配置。应用在途限制不是跨实例公平限流。
- **持久性及容灾。** 在预发按实际拓扑演练数据库进程/主节点故障、备份恢复与PITR、复制延迟、主从切换、旧请求重放，记录RPO/RTO。应用层未知提交测试不等于物理断电或主从故障转移已经通过。
- **运营控制。** 监控47011、503、连接池等待、死锁重试与待审积压；定期完成三游标全量对账；保护ID=1顶级管理员和资金凭证存储。人工审核仍要核验真实到账，不能将凭证号存在当成到账证明。

## 复现

`bash server/tests/wallet/run.sh`启动专属MySQL测试容器并自动清理，执行全仓、race、clientFoundRows、查询计划/负载、fuzz、vet/build；`WALLET_RUN_VULN=1`追加漏洞扫描。结果文件可通过绝对路径`WALLET_LOAD_RESULT`指定。管理端执行`pnpm install --frozen-lockfile && pnpm run test:wallet && pnpm run build`。

新增`.github/workflows/wallet.yaml`供push/PR执行；本轮已本机执行对应测试命令，尚未在远端CI运行该工作流。只使用专用本机测试库，不允许将测试DSN改成业务库。
